## What changed (per file, minimal pure-type)

**36 TS2379 fixes (chart-line-* component files):** Inline options
type `{ X?: number }` -> `{ X?: number | undefined }` per dispatch
instruction. The optional value at the call site is unchanged; only
the target type annotation gains `| undefined`.

**1 TS2322 fix (chart-chord.tsx):** The `ChordArc` interface field
`color?: string` is widened to `color?: string | undefined`. The
source object `{ color: cat.color }` where `cat.color: string |
undefined` now assigns cleanly. Pure-type interface widening.

**2 TS6133 fixes (genuinely unused):**

- `chart-funnel.tsx(219,32)`: The map callback
  `stages.map((s, i) => ...)` never reads `i`. Removed the unused
  `i` parameter: `stages.map((s) => ...)`. `Array.prototype.map`
  passes positional args only when the callback declares them; the
  produced array is identical. Pure behavioral equivalence.

- `chart-line-bollinger.tsx(702,5)`: The component-level destructured
  prop `bandColor = DEFAULT_CHART_LINE_BOLLINGER_BAND_COLOR` is
  shadowed at line 541 by a per-series local
  `const bandColor = s.bandColor ?? DEFAULT_...` and never read at
  the component level. Removed the unused destructured binding.
  The prop is still in the public type interface
  (`ChartLineBollingerProps.bandColor?: string`) and remains
  acceptable on the caller side. Behavior is identical to before
  because the outer `bandColor` was always shadowed.
