non-showcase) utility code that keep the build gate red. Scope is the

## Edits

- **use-focus-trap.ts L52, L77, L82**: `focusables[0]` /
  `focusables[focusables.length - 1]` are typed `HTMLElement | undefined`
  under `noUncheckedIndexedAccess`. Used `?.focus()` (the minimal
  undefined guard the dispatch suggests) so the call no-ops on the
  impossible-in-practice undefined while keeping observed runtime
  unchanged.
- **use-local-storage.ts L59, L60**: `(fallback as Record<string,
  unknown>).key = ...` accesses an index-signature property via dot.
  Switched to bracket access `['key']` and `['newValue']`. Same
  reference assignment, just satisfies
  `noPropertyAccessFromIndexSignature`.
- **ab-variant.ts L56, L57, L59**: `norm[i]` is `number | undefined`
  and `VARIANT_IDS[i]` is `VariantId | undefined`. The function
  signature returns `VariantId`. Used `??` to substitute a safe
  default at each access -- `cumulative += norm[i] ?? 0` and
  `VARIANT_IDS[i] ?? 'A'`. These fallbacks are unreachable in practice
  (the loop is bounded by both arrays' lengths) but make the type
  narrow correctly.
- **error-reporter.ts L87, L127, L149, L172**: Under
  `exactOptionalPropertyTypes`, building an `ErrorRecord` or calling
  `report(...)` with `string | undefined` values for the optional
  `stack` / `componentStack` / `url` fields was invalid because the
  type `stack?: string` does NOT include explicit undefined. Widened
  the optional fields in both `ErrorRecord` and `ReportInput` to
  `stack?: string | undefined`, etc. -- "where it is genuinely
  optional" per the dispatch (these fields ARE genuinely optional;
  the callers already pass `undefined` deliberately).
- **form-validation.ts L8, L60**: Same exactOptionalPropertyTypes
  pattern. `const PASS: ValidationResult = { error: undefined }` and
  `return { error: undefined }` failed against
  `ValidationResult = { error?: string }`. Widened the type to
  `error?: string | undefined`.
- **use-metrics.ts L108**: TS2769 "No overload matches this call" on
  `fetch('/api/metrics', { headers: token ? {...} : undefined })`.
  Same pattern fixed in WorkerResourceGraph in 11.1101 -- rebuild
  init so `headers` is only set when a token exists, never an explicit
  `headers: undefined`. Behaviour identical: token present -> attached;
  token missing -> no header.
- **use-workspace-prefs.ts L1**: TS6133 `useCallback` imported but
  never used. Removed it from the named-imports list.

## Risk

- Pure subtractive / minimal-additive type changes. Two interface
  widenings (`ErrorRecord` + `ReportInput` in error-reporter,
  `ValidationResult` in form-validation) widen `T?:` to `T? | undefined`
  -- structurally identical except now `T | undefined` is assignable
  back into the optional slot, which is what every existing call site
  already does. No new runtime branches, no behaviour change in the
  fallback values (`?? 0` and `?? 'A'` in ab-variant cover paths the
  loop never reaches in practice).
