# 11.1112 -- CHORE: fix 31 source-confirmed tsc strict-type errors in 8 src/lib test files (v1.11.1130)

## Scope

The project tsconfig type-checks tests, so `tsc --noEmit` reports
strict-type errors in src/lib unit tests too. This batch covers 8
test files / 31 errors. Scope is the 8 dispatched files plus three
unavoidable cascade-exposed peers (see "Cascade" below). No
production source touched; no `as any` / `ts-ignore`; no test
assertion was changed.

## Cascade: 3 peer files unmasked by the dispatched fixes

TypeScript's diagnostic engine reports only the FIRST error in a
dependency chain; once that error is fixed, the next downstream error
becomes visible on the next run. As the 8 dispatched fixes landed,
three peer .test.ts files surfaced a latent TS2488 each (the
`const [...] = (X as Mock).mock.calls[0]` destructure-from-possibly-
undefined pattern). Empirically verified: reverting the
use-batch-submit edit causes use-control-panel-single L127 to
disappear from tsc output, and re-applying it re-exposes it. The
pattern was always there; the cascade just made it visible.

To satisfy the dispatch's mandatory "no new errors anywhere" check,
the same minimal `mock.calls[0] -> mock.calls[0]!` fix was applied to
every site in:

- `use-control-panel-single.test.ts` (4 occurrences via
  `replace_all`; only L127 actively errored, the other 3 were
  defensive same-pattern fixes so the cascade cannot re-surface).
- `use-worker-action-strip.test.ts` (4 occurrences via sed).
- `use-worker-selection.test.ts` (3 occurrences via sed).

These edits are pure non-null assertions on call destructures gated by
prior `toHaveBeenCalled` expectations; they neither change test
assertions nor introduce new types.

## Risk

- Pure type-level edits. The `null as T | null` cast-inits are
  equivalent at runtime (`null` value either way); the cast just
  preserves the declared union so flow-typing does not narrow to the
  `null` literal. The non-null `!` assertions are gated by
  `toHaveBeenCalled` checks. The `[len-1]?.[0]` rewrite preserves the
  semantics of `.at(-1)?.[0]`. The `Record<string, unknown>` bracket
  access keeps `receivedBody?.['namePrefix']` returning the same
  value.
- The 3 cascade-exposed peer files received the same defensive
  pattern fix; their colocated tests still pass.
