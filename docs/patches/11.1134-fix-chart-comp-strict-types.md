# 11.1134 - fix 32 source-confirmed tsc strict-type errors in 32 chart component files (chart bucket batch 14, fifth component batch)

## Scope

Fifth chart **component** source batch. 32 chart `.tsx` component
files, exactly 1 TS2379 each (32 total). Every fix is PURE TYPE -
erased at compile, zero JS emission change, zero rendered output
change.

## Baseline (HEAD before this patch)

`tsc --noEmit -p web/tsconfig.json`: 191 errors total, 32 in the 32
target files (1 each, all TS2379 exactOptional).

## After this patch

`tsc --noEmit -p web/tsconfig.json`: **159** errors total, **0** in
the 32 files. Delta = 191 - 159 = **-32**. Zero new errors anywhere.
`.test.*` files still at zero project-wide. Non-chart-component
files still at zero project-wide.

## What changed (per file, minimal pure-type)

All 32 files have inline options types of the form
`options: { ... X?: number; ... } = {}` with TS2379 at the call
site complaining about `{ X: number | undefined }` not being
assignable to `{ X?: number }` under `exactOptionalPropertyTypes`.

Per the dispatch's exact instruction: add `| undefined` to each
optional property of the TARGET inline option type in the same
file. The fix is purely the type annotation; the value at the call
site is unchanged.
