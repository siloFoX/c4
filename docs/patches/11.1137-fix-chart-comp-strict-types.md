## What changed (per file, minimal pure-type)

41 of 42 files have inline options types of the form
`options: { ... X?: number; ... } = {}` with TS2379 at the call
site complaining about `{ X: number | undefined }` not being
assignable to `{ X?: number }` under `exactOptionalPropertyTypes`.

Per the dispatch's exact instruction: add `| undefined` to each
optional property of the TARGET inline option type in the same
file. The fix is purely the type annotation; the value at the call
site is unchanged.

The remaining file `chart-line-fisher.tsx` has a single TS2322 at
line 230: `trigger[i] = fisher[i - 1];` where `fisher[i - 1]` is
`number | null | undefined` (under `noUncheckedIndexedAccess`) but
target `trigger[i]` is `number | null`. The loop bound `1 <= i < n`
guarantees `fisher[i - 1]` is in bounds, so the safe pure-type fix
is a non-null assertion: `trigger[i] = fisher[i - 1]!;`. Non-null
`!` is allowed by the dispatch's policy.
