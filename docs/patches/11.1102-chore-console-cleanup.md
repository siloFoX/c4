# 11.1102 -- CHORE: remove leftover debug console.log from page components (v1.11.1120)

## Scope

A source scan found 5 stray debug `console.log` calls left in shipped
page components, not gated behind any debug flag. The lint pipeline is
tsc-only and does not catch `no-console`, so they spammed the browser
console in production builds.

| File | Line | Log |
|---|---:|---|
| web/src/pages/Config.tsx | 248 | `console.log('[config] import file', files[0]?.name, files[0]?.size)` |
| web/src/pages/Templates.tsx | 326 | `console.log('[templates] import file', files[0]?.name, files[0]?.size)` |
| web/src/pages/Snapshots.tsx | 569 | `console.log('[snapshots] import staged', files[0]?.name)` |
| web/src/pages/Profiles.tsx | 180 | `console.log('[profiles] import staged', files[0]?.name)` |
| web/src/pages/Health.tsx | 636 | `(v) => console.log('[health.rating]', v)` |

## Edits

- **Config / Templates**: each log lived inside a file-import handler
  (`onFiles` / `onAdd`) that also called `setError(null)`. Removed the
  log + its now-orphan `// eslint-disable-next-line no-console` and
  dropped the now-unused `(files)` param so the handler stays tsc-clean
  under `noUnusedParameters`. The `setError(null)` real behaviour is
  preserved.
- **Snapshots / Profiles**: each log was the SOLE body of an `onAdd`
  handler. Since `onAdd` is optional on `FileDrop` (the call site is
  `onAdd?.(newOnes)`), dropped the entire prop -- no empty no-op
  handler left behind. FileDrop's own staged-file UI is unchanged.
- **Health**: the log was the only body of a `Rating`'s `onChange`.
  `Rating.onChange` is optional but its absence flips the widget to
  readonly (`readonly = readonlyProp ?? onChange == null`), which would
  be a visible behaviour change. Replaced with `onChange={() => {}}`
  so the rating stays interactive. Behaviour is identical to before:
  click cycles the hover/highlight but does not persist (the rating's
  `value={0}` is hard-coded; wiring to telemetry is a separate task).

## Verification (mandated)

- `grep -n "console.log" Config.tsx Templates.tsx Snapshots.tsx Profiles.tsx Health.tsx` returns ZERO hits.
- `tsc --noEmit` adds no new errors in the 5 changed files. Three
  pre-existing tsc errors (Profiles:408 RadioGroup, Templates:3 unused
  `LoadingSkeleton`, Templates:342 Textarea) are on lines I did not
  touch and exist on pristine main.
- `vitest` on the 5 page test files: 178 of 179 pass; the 1 failing
  test (`Health.test.tsx > does NOT render the loading skeleton when
  data is already present`) was verified to ALSO fail on pristine main
  before my edit, so the chore introduces no regression.

## Risk

- Pure subtractive change. No behaviour change at the user-visible
  level: import handlers still clear errors (Config/Templates),
  FileDrops still stage files (Snapshots/Profiles), the Health rating
  is still interactive (just no longer logs on click).
