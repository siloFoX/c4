# 11.1103 -- CHORE: fix 4 TS2308 barrel re-export collisions in ui/index.ts (v1.11.1121)

## Scope

`tsc --noEmit` reported 4 TS2308 duplicate-export errors from
`web/src/components/ui/index.ts` re-exporting the same name via
`export * from` two different modules:

| Name | Earlier exporter | Later exporter |
|---|---|---|
| `detectPlatform` | `./kbd` | `./keyboard-shortcuts-overlay` |
| `ExportFormat` | `./export-button` | `./data-export` |
| `AnsiSegment` | `./cmd-history` | `./log-stream` |
| `parseAnsi` | `./cmd-history` | `./log-stream` |

## Ground-truthed before editing

- All 4 TS2308 errors confirmed present in tsc output at lines 141,
  142, 145 of ui/index.ts before any change.
- Each pair has TWO PARALLEL DEFINITIONS (not one re-importing the
  other). `kbd.tsx:78` and `keyboard-shortcuts-overlay.tsx:71` each
  define their own `detectPlatform` with DIFFERENT return types
  (`KbdPlatform` vs `KeyboardPlatform`). `data-export.tsx:28`
  (`'csv' | 'json' | 'xlsx'`) and `export-button.tsx:15`
  (`'csv' | 'json'`) define different `ExportFormat` unions.
  `cmd-history.tsx:86` (`{text, style: AnsiStyle}`) and
  `log-stream.tsx:185` (`{text, fgColor?, bgColor?, bold?, italic?,
  underline?, dim?}`) define structurally different `AnsiSegment`
  shapes.
- A repo-wide grep for external consumers of these 4 names from the
  `ui` barrel returned ZERO. (`shortcut-keymap.ts` has its own third
  `detectPlatform` and its test imports from `./shortcut-keymap`, not
  from `ui`.) So the canonical pick for the barrel has zero runtime
  impact on the codebase today.

## Fix (single file: ui/index.ts)

Used the TS-suggested disambiguation pattern: an explicit named
re-export shadows the implicit `export *` ambiguity, without touching
either source module's exports. Added 4 lines (one per symbol) after
the conflicting `export *` block:

```ts
export { detectPlatform } from './kbd';
export type { ExportFormat } from './data-export';
export type { AnsiSegment } from './cmd-history';
export { parseAnsi } from './cmd-history';
```

Canonical owners chosen:
- `detectPlatform` -> `./kbd` (the kbd primitive is more fundamental
  than the overlay; also the earlier exporter in the barrel, so this
  matches the implicit-winner behaviour before tsc started erroring).
- `ExportFormat` -> `./data-export` (the comprehensive export-format
  module: type + `DEFAULT_EXPORT_FORMATS` + `DEFAULT_EXPORT_FORMAT` +
  `EXPORT_FORMAT_LABELS`. `export-button.tsx` defines its own narrower
  `'csv' | 'json'` -- the data-export superset is the conceptual
  owner).
- `AnsiSegment`, `parseAnsi` -> `./cmd-history` (earlier exporter;
  also where the ANSI parsing primitive predates the log-stream
  version. Conservative pick that matches the implicit-winner
  behaviour).

The source modules' own `export function detectPlatform` /
`export type ExportFormat` / `export interface AnsiSegment` /
`export function parseAnsi` declarations are UNCHANGED. Each module
continues to use its own local definition internally. The change is
solely which version barrel consumers see.
