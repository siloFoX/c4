# 11.1104 -- FIX: revert 344 chart-line TS1312 regressions from the 11.1100 codemod (v1.11.1122)

## Scope

`tsc --noEmit` reported 344 TS1312 errors in
`web/src/components/ui/chart-line-*.tsx`:

```
src/components/ui/chart-line-absolute-momentum.tsx(367,12): error TS1312:
  Did you mean to use a ':'? An '=' can only follow a property name when
  the containing object literal is part of a destructuring pattern.
```

## Root cause -- my own 11.1100 bulk guard

The v1.11.1118 bulk guard (TODO 11.1100) walked
`web/src/components/ui/chart-line-*.tsx` looking for the props destructure
line `    series,` (exactly one occurrence per file, to avoid touching
ambiguous files) and replaced it with `    series = [],` -- a
destructure-default that prevents a missing `series` prop from crashing
`.reduce(...)` etc.

That codemod intent is correct for component-props destructures. But the
`^    series,$` regex ALSO matched a shorthand-key entry that appears in
some chart-line helper functions' return-object literals:

```ts
function getRun(...) {
  const series = getLineAbsoluteMomentumFinitePoints(data) ...;
  // ...
  return {
    series,        // shorthand-key referencing the local `series` const
    length,
    strongThreshold,
    // ...
  };
}
```

After the 11.1100 codemod, this line became `series = [],` which is a
syntax error inside an object expression (TS1312). The 388 files my
codemod modified break down as:
- 344 files had `series,` in a return-object-literal context (now
  broken).
- 44 files had `series,` in a destructure context (correctly fixed by
  11.1100; left untouched here).

Why this slipped through 11.1100's tsc validation: my tsc check was
piped through `| head -40`, so 344 TS1312 lines were truncated and not
visible in the captured output. The gallery e2e ALSO passed because
only the 41 registry-listed chart-line components ever get loaded by
the gallery; the other 347 chart-line files (including the 344 broken
ones) are dormant -- vite never transpiles them, so no runtime crash
exposed the syntax error.

## Fix -- revert to the original line, not the dispatch's `series: [],`

The dispatch wording prescribed `series = [],` -> `series: [],`. That
would type-check (it's a valid empty-array property), BUT this is a
helper function whose return value is destructured downstream as e.g.
`run.series.length`, `run.series.map(...)` (see lines 446, 544, 843,
1049 of chart-line-absolute-momentum.tsx and the equivalent in every
sibling). Setting `series: [],` would silently return an empty array on
every call and break the chart's data flow.

The pre-11.1100 source confirms the original line was `    series,`
(shorthand-key). The CORRECT revert is back to that exact prior state,
which keeps both:
- tsc happy (zero TS1312), and
- runtime behaviour identical to pre-11.1100 (the chart's data flow is
  restored).

## Codemod

Strictly tsc-driven. The fix script reads the captured tsc log
(`/tmp/tsc-11.1104.log`) and, for every `(file, line)` pair tsc reports
as TS1312, validates the line is exactly `    series = [],` and rewrites
it to `    series,`. The 44 files where the 11.1100 codemod correctly
added a destructure-default `series = []` (no TS1312 there) are NEVER
touched -- the tsc list is the authoritative scope.

## Verification (mandated)

- `tsc --noEmit` TS1312 count: **344 -> 0**. Total tsc errors dropped
  from 1470 to 1126 (delta = 344, matches exactly -- zero new errors
  introduced).
- e2e (`web/e2e/gallery-no-crash.spec.ts`, 11.1100): **1 passed (8.9s)**
  -- all 41 registry tiles still mount, zero page errors, zero "Chart
  failed" UIErrorBoundary tiles.

## Risk

- Zero behaviour change for the 41 registry tiles (the only consumers).
- The 303 non-registry chart-line files (344 broken minus 41 in
  registry; well, technically all 344 fixes are non-registry since the
  registry tiles use the canonical primitives which my codemod did NOT
  touch -- the registry includes ChartLineRsi etc. which were on the
  ambiguous-skip list) now compile cleanly and would behave correctly
  if added to the registry later.

## Follow-up note

The 11.1100 bulk guard remains worth keeping for the props-destructure
defaults it correctly added in the 44 files where `series,` was a
component-props destructure -- those continue to guard against the
missing-prop crash that 11.1100 was scoped to fix. The
return-object-literal collateral is what this dispatch reverts.
