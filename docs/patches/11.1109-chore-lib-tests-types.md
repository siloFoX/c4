# 11.1109 -- CHORE: fix 30 source-confirmed tsc strict-type errors in 4 src/lib unit test files (v1.11.1127)

## Scope

The project tsconfig type-checks tests (single tsconfig, include `src`,
no test exclude), so `tsc --noEmit` reports strict-type errors in
src/lib unit tests too. This batch covers 4 lib test files / 30 errors
in total. Scope is ONLY those 4 files; no edits to non-test source; no
`as any` / `ts-ignore`. Per the dispatch, non-null assertion (`!`) is
allowed where the test setup guarantees presence.

## Edits

| File | Count | Codes | Pattern |
|---|---:|---|---|
| `web/src/lib/error-reporter.test.ts` | 12 | TS2532 | Non-null assertion `!` on `all[N]`, `windowRecs[0]`, `listener.mock.calls[0]`, `createUrl.mock.calls[0]`. Every site is preceded by an assertion that pins the array length (`toHaveLength(2)`, `toHaveLength(50)`, `toHaveLength(1)`, `toBeGreaterThanOrEqual(1)`, `toHaveBeenCalledTimes(1)`), so the index is guaranteed present at runtime. |
| `web/src/lib/use-history-worker-detail.test.ts` | 6 | TS4111 | Bracket access on the msw path-params object: `params.name` -> `params['name']`. The msw handler types `params` as an index-signature record, which under `noPropertyAccessFromIndexSignature` requires bracket notation. |
| `web/src/lib/use-filtered-sessions.test.ts` | 6 | TS2532 | Non-null assertion `!` on `result.current.filteredGroups[0]`. Each test's setup builds a `groups` array whose first entry is guaranteed to survive the filter being tested. |
| `web/src/lib/use-audit-export.test.ts` | 6 | TS2339 | Three `let X: URLSearchParams \| null = null;` declarations switched to `let X = null as URLSearchParams \| null;`. The literal `let X: T \| null = null;` form had narrowed TS's flow-typing of `X` to the exact `null` literal (the reassignment happens inside the msw closure, which TS does not follow). When the test later did `X?.get(...)`, the optional-chain unwrap of `null` evaluated `.get` on `never`, which produced TS2339. Casting the initial value with `as URLSearchParams \| null` preserves the declared union and prevents the narrow-to-`null` (fixes all 6 `.get(...)` accesses on `params`, `captured`, `lastParams`). |

No test assertion was changed; runtime behaviour is identical.

## Risk

- Pure type-level edits.
- Each `!` is gated by a length / call-count expectation a line or two
  above, so the assertion never throws at runtime in the test bodies.
- The `null as URLSearchParams | null` initializers are equivalent to
  the original at runtime (both yield the `null` value); the cast just
  preserves the union annotation so flow-typing does not collapse to
  the `null` literal.
- Bracket access (`params['name']`) on the msw index-signature record
  yields the same string value as dot access.
