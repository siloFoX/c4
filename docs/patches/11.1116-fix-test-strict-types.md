# 11.1116 - fix 24 source-confirmed tsc strict-type errors in 11 test files

## Scope

The dispatch named 11 test files (8 `src/lib/*.test.ts` + 1
`src/lib/*.test.tsx` route helper) holding strict-type errors under
`exactOptionalPropertyTypes` / `noUncheckedIndexedAccess` /
`noPropertyAccessFromIndexSignature` / `noUnusedLocals`. The dispatch
quoted "26 errors"; a fresh `tsc --noEmit` baseline against HEAD found
**24** errors across the same 11 files (the dispatch slightly over-
counted), and every one of them is now fixed.

## What changed (per file, minimal)

- **HelpDrawer.test.tsx** -- 3x `active[0].getAttribute(...)` -> `active[0]!.getAttribute(...)` (test guarantees `toHaveLength(N)` above).
- **MeetingsForkForm.test.tsx** -- 3x `modeSelect.getAttribute(...)` / `trackSelect.getAttribute(...)` -> `modeSelect!.getAttribute(...)` / `trackSelect!.getAttribute(...)` after `getByRole('combobox', {...})` (presence asserted above).
- **use-escalation-resolve.test.ts** -- `params.id` -> `params['id']` (sed) for bracket-access on msw `:id` param; `.at(-1)` -> `[len-1]` index access (ES2022 `.at` not in project lib target).
- **use-meeting-contribute.test.ts** -- `let body: { vote?: string; reason?: string } | null = null;` was being narrowed to `never` by TS flow analysis through msw closure; switched to `let body = null as { vote?: string; reason?: string } | null;` so the union type sticks.
- **use-meeting-state-action.test.ts** -- `params.id` and `params.action` -> bracket access.
- **use-rbac.test.ts** -- `new Promise(() => {})` had no inferable type for the msw resolver's return; gave it `new Promise<HttpResponse>(() => {})` (default body type) which satisfies `AsyncResponseResolverReturnType<DefaultBodyType>`. Separately, `users[0].grants` -> `users[0]!.grants` after `toHaveLength(2)` guarantees presence.
- **use-specialist-enrichment.test.ts** -- `params.id` -> `params['id']`; `initialProps: { id: 'spec-x' }` -> `initialProps: { id: 'spec-x' as string | null }` so the subsequent `rerender({ id: null })` keeps the same shape (rather than the inferred `{ id: string }`).
- **use-specialist-tag-editor.test.ts** -- 2x `mock.calls[0][0]` -> `mock.calls[0]![0]` (length asserted by `toHaveBeenCalledTimes`).
- **use-worker-action-strip.test.ts** -- `variant: 'primary'` -> `variant: 'default'` (the source `Action.variant` union does not include `'primary'`; `'default'` is its idiomatic equivalent and the assertion does not depend on the literal); rerender callback parameter now typed `(message: string, type: ToastType) => void` (imported `ToastType` from `../components/Toast`) so it matches the production signature.
- **use-workflow-runs.test.ts** -- `params.id` -> `params['id']`; `initialProps: { id: 'wf1' }` -> `initialProps: { id: 'wf1' as string | null }` for the same reason as use-specialist-enrichment.
- **use-xterm-theme-tracking.test.ts** -- removed unused `vi` from the vitest import (no `vi.` calls in the body); removed stale `// @ts-expect-error - assign fake.` line; the assignment now typechecks via `globalThis.MutationObserver = FakeMO as unknown as typeof MutationObserver`.
