# 11.1147 - isolate the i18n detectLocale empty-localStorage test from shared beforeEach

## Scope

`src/lib/i18n.test.ts` case `detectLocale falls back to the navigator
language when localStorage is empty` failed (expected `ko`, got `en`).
Root cause was pre-confirmed by the dispatch: the shared `beforeEach`
(lines 19-25) runs `window.localStorage.clear()` and then
`setLocale(DEFAULT_LOCALE)`, and `setLocale` WRITES the default back
to localStorage via the same persistence path `detectLocale` reads
from. So by the time this case's body runs, localStorage already
carries the saved default, `detectLocale` returns it early (i18n.ts
line 26-27) and never reaches the navigator-language fallback
(i18n.ts line 33: `nav.toLowerCase().startsWith('ko')`).

The detectLocale source IS correct: with an actually-empty
localStorage and `navigator.language === 'ko-KR'`, the fallback
correctly returns `ko`.

## Fix

Add `window.localStorage.removeItem(LOCALE_KEY)` at the start of the
single failing test body. This narrowly clears the persisted locale
just for this case so the empty-localStorage precondition the test
documents in its name actually holds. Sibling tests are unaffected;
the shared beforeEach is unchanged; no source files touched; the
assertion is preserved verbatim (`expect(detectLocale()).toBe('ko')`).

A multi-line comment block names the bug, the beforeEach interaction,
and the source line numbers that produce the early-return so a
future reader does not have to re-derive it.
