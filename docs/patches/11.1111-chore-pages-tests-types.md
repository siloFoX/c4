# 11.1111 -- CHORE: fix 26 source-confirmed tsc strict-type errors in 11 src/pages test files (v1.11.1129)

## Scope

The project tsconfig type-checks tests, so `tsc --noEmit` reports
strict-type errors in page tests too. This batch covers 11 files / 26
errors. Scope is ONLY those 11 files; no non-test source edits; no
`as any` / `ts-ignore`; no test assertion was changed. Helper signature
widening + return-type cast preserve test semantics (callers can still
pass `{ field: undefined }` overrides to test the undefined-flag path).

## Edits

### Dominant pattern (17 TS2379, 4 TS2375): helper-signature widening + return cast

9 page tests share a `makeX(over: Partial<T> = {}): T` helper that
spreads `over` into a defaults object and returns the merged payload.
Tests intentionally pass `{ field: undefined }` to exercise
"field absent" rendering. Under exactOptionalPropertyTypes, the
literal `{ field: undefined }` violates `Partial<T>`'s slot
`field?: T[K]` (no explicit undefined). Two-step type-only fix:

1. Widen the helper's `over` parameter from `Partial<T>` to a mapped
   type that explicitly allows undefined per field:
   `{ [K in keyof T]?: T[K] | undefined }`.
2. After step 1, the spread `{ ...defaults, ...over }` can carry an
   undefined into a required slot in `T`, so the helper return is
   asserted `as T`. This is a typed assertion (not `as any`) and
   matches the test's runtime intent (`over` wins the spread).

Applied to all 9 helpers across 9 files:
`Health.makeHealth / Morning.makeReport / Profiles.makeProfile /
Scribe.makeStatus / Scribe.makeContext / Swarm.makeNode /
Templates.makeTemplate / TokenUsage.makeData /
Validation.makeReport`.

### Direct-literal exactOptional sites (2 TS2375 / TS2352)

- `Morning.test.tsx:205` -- `{ content: undefined, sections: [...] }`
  is built inline (not via helper). Cast `as unknown as
  MorningResponse` to satisfy exactOptional; double-cast is required
  because tsc reports "neither type sufficiently overlaps" on the
  single-step cast.
- `Swarm.test.tsx:323` -- same shape for `{ name, children: undefined }`
  -> `as unknown as SwarmNode`.

### Possibly-undefined (TS2532) and arg-mismatch (TS2345)

- `Morning.test.tsx:311 + L336` -- `md[0].getAttribute(...)` ->
  `md[0]!.getAttribute(...)`. Each test asserts
  `expect(md).toHaveLength(1)` a line above, so the index is gated.
- `Rbac.test.tsx:326` -- `within(usersUl)` where `usersUl =
  uls[uls.length - 1]` is `HTMLUListElement | undefined`. The test
  asserts `uls.length >= 1` two lines above. Non-null assert
  `within(usersUl!)`.

### Unused declarations (TS6133)

- `Queue.test.tsx:45 + L46` -- `resolveGet` / `resolvePost` were
  write-only `let` variables (declared, reset in beforeEach, never
  read). Removed the declarations AND the two `beforeEach` resets;
  nothing else in the file references them.
- `Templates.test.tsx:2` -- removed `within` from the
  `@testing-library/react` named imports.
- `UIDemoRoute.a11y.test.tsx:2` -- removed `expect` from the
  `vitest` named imports.

## Risk

- Pure type-level edits.
- The 9 helper-signature widenings + return casts are equivalent at
  runtime: the spread merges defaults with overrides exactly as
  before. The cast lets tsc accept the spread result when an
  override sets a required field to undefined (the intentional
  test-the-undefined-path case).
- The two `as unknown as T` casts cover inline literals that the
  test passes to a hookState slot whose type came from the
  production source; the renderer already handles undefined in those
  slots (the tests exist precisely to verify that).
- All `!` assertions are gated by an explicit length / membership
  expectation a line or two above. The TS6133 removals drop
  truly-dead writes (variable was written but never read).
