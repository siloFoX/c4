# 11.1105 -- CHORE: fix 19 stale prop-type errors in UIDemoRoute.tsx (v1.11.1123)

## Scope

`tsc --noEmit` reports 19 errors in
`web/src/pages/UIDemoRoute.tsx` (16 TS2322 + 3 TS2741). UIDemoRoute is
the feature-flag-gated Storybook-style visual-QA gallery (registry id
`ui-demo`); it is imported only by `registry.ts` lazy-load and its own
tests, so the regression is bounded and cannot leak into a production
page. Fix scope is ONLY this one file -- no edits to components.

## Edits (per error)

All 19 errors are stale prop usages whose component API has since
narrowed. Edits picked the nearest valid enum / corrected the prop
name / added the now-required `id`:

| Line | Before | After | Why |
|---:|---|---|---|
| 114 | `Button variant="primary"` | `variant="default"` | `primary` was renamed to `default` |
| 123 | `Badge variant="muted"` | `variant="neutral"` | `muted` -> `neutral` |
| 126 | `Badge variant="danger"` | `variant="destructive"` | `danger` -> `destructive` |
| 128-130 | `BadgeCounter value={N}` | `count={N}` | prop is `count`, not `value` |
| 134-137 | `StatusDot tone="..."` | `variant="online" / "busy" / "offline" / "unknown"` | `tone` removed; the type is now `StatusDotVariant = online|busy|away|offline|unknown` |
| 138-140 | `StatusPill tone="..." {label as children}` | `<StatusPill status="online/busy/offline" label="..." />` | `tone` removed; `status: StatusPillStatus` (`online|busy|idle|offline|error`) is required and the type Omits `children` so the label is via the `label` prop |
| 163 | `Checkbox onChange={setCheckboxValue}` | `onChange={(e) => setCheckboxValue(e.target.checked)}` | Checkbox's `onChange` is `ChangeEventHandler<HTMLInputElement>`, not a state setter |
| 187 | `Alert variant="danger"` | `variant="error"` | `AlertVariant = info\|success\|warning\|error\|neutral`; `danger` -> `error` |
| 235-237 | `{ label, href? }` (no id) | `{ id, label, href? }` | `BreadcrumbItem.id` is required |
| 243 | `Tooltip content="..."` | `label="..."` | `TooltipProps.label`, not `content` |

The dispatch text attributed the L163 onChange error to `Switch`, but
tsc actually reports L163 col 17 = the **Checkbox** (Switch sits at
L158 and was never erring -- its own `onChange` declared as
`(checked: boolean) => void` accepts a `Dispatch<SetStateAction<boolean>>`
fine via parameter contravariance). Fixed the actual offender:
Checkbox. Left Switch alone.

No `as any` / no `ts-ignore` / no `ts-expect-error`. No edits outside
`web/src/pages/UIDemoRoute.tsx`.
