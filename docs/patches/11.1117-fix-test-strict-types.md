# 11.1117 - fix 20 source-confirmed tsc strict-type errors in 10 test files

## Scope

The dispatch named 10 test files (3 `src/lib/*` + 5 `src/components/*` +
2 `src/components/ui/*` + 1 `src/i18n/*`) holding strict-type errors
under `exactOptionalPropertyTypes` / `noUncheckedIndexedAccess` /
`noPropertyAccessFromIndexSignature` / `noUnusedLocals`. Quoted as 20;
fresh `tsc --noEmit` baseline confirms **20** errors across the same 10
files. All 20 are now fixed.

## Baseline (HEAD before this patch)

`tsc --noEmit -p web/tsconfig.json`: 846 errors total, 20 spread across:

| file | errors | TS codes |
|------|-------:|----------|
| `web/src/lib/portal-root.test.ts` | 2 | TS2578 (Unused `@ts-expect-error`) |

| `web/src/i18n/i18n-keys.test.ts` | 2 | TS2345 (string \| undefined -> string) |

## After this patch

`tsc --noEmit -p web/tsconfig.json`: **826** errors total, **0** across
the same 10 files. Delta = 846 - 826 = **-20**. Zero new errors anywhere.

## What changed (per file, minimal)

- **portal-root.test.ts** -- removed two stale `// @ts-expect-error - intentional teardown for SSR branch.` lines (the surrounding cast `(globalThis as { document?: unknown })` already typechecks the `delete`).
- **conversation-render.test.tsx** -- 2x `circular.self = circular` -> `circular['self'] = circular` (bracket access for index-signature property).
- **i18n-keys.test.ts** -- 2x `keys.add(m[1])` -> `keys.add(m[1]!)` (the global capturing regex guarantees `m[1]` is the matched group; non-null at the test layer).
- **WorkflowGraph.test.tsx** -- the `makeWorkflow` helper had `nodes,` and `edges,` both before AND after the `...overrides` spread (TS1117 duplicate key). Kept the trailing pair (so the helper's `nodes`/`edges` win over any caller `overrides`) and dropped the earlier ones.
- **toolbar.test.tsx** -- 2x `items[i] as { onClick: ... }` -> `items[i] as unknown as { onClick: ... }` (the TS-suggested "convert to unknown first" path for type-incompatible casts).
- **timeline.test.tsx** -- 2x `headers[i].getAttribute(...)` -> `headers[i]!.getAttribute(...)` (`expect(headers).toHaveLength(2)` two lines up guarantees presence).
- **tag-input.test.tsx** -- replaced 8x direct `prop={props.X}` passes with a small inline `opt()` helper that conditionally spreads `{ X: v }` only when `v !== undefined`. Mirrors the canonical exactOptionalPropertyTypes fix without `as any`. Also removed the unused `const user = userEvent.setup();` from the `maxTags caps additions` it (only `render`/`screen.queryByLabelText` are used) and switched the `it` callback to non-async since `await` is no longer called.
- **SpecialistsAuditPanel.test.tsx** -- 2x `within(items[i]).getByText(...)` -> `within(items[i]!).getByText(...)` after presence is established by `querySelector('ul')`.
- **SessionsComparisonCard.test.tsx** -- `headers[0].textContent` -> `headers[0]!.textContent` after `expect(headers).toHaveLength(3)`; and the `<SessionsComparisonCard className={undefined} />` test now renders without the prop (the prop is optional and the test name "treats an undefined className the same as no className" -- exactly what no-prop does). Both branches still hit the `max-w-md` assertion.
- **MeetingsStagesView.test.tsx** -- 2x `cards[i].textContent` -> `cards[i]!.textContent` after `Array.from(wrapper.children)`.

## Verification

- `tsc --noEmit -p web/tsconfig.json`:
  - Baseline (HEAD): 846 total, 20 in target files.
  - After: 826 total, 0 in target files.
  - Net: -20, no new errors anywhere.
- `npx vitest run` on the 10 files: **8 files pass, 2 files have
  pre-existing failures (6 tests total)** -- baseline and post-fix runs
  show the SAME 2 failed files / 6 failed tests count. No NEW failures
  introduced by this patch (confirmed by stashing the fix and re-running
  vitest -- identical 6 failed / 230 passed result).
- No `as any`, no `ts-ignore`, no fresh `ts-expect-error` (two stale
  ones removed in `portal-root.test.ts`).
- No edits outside the 10 dispatched files.
- No test assertion behaviour changed. The
  `<SessionsComparisonCard className={undefined} />` -> no-prop swap is
  a semantic equivalence under React (optional prop missing == optional
  prop set to undefined); the assertion against `max-w-md` still
  matches because the source has a default `max-w-md` class.
