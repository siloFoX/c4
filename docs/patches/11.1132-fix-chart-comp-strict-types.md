# 11.1132 - fix 48 source-confirmed tsc strict-type errors in 24 chart component files (chart bucket batch 12, third component batch)

## Scope

Third chart **component** source batch. 24 chart `.tsx` component
files holding 48 errors total (exactly 2 each). Every fix is PURE
TYPE - erased at compile, zero JS emission change, zero rendered
output change.

## Baseline (HEAD before this patch)

`tsc --noEmit -p web/tsconfig.json`: 282 errors total, 48 in the 24
target files (2 each).

Error mix:
- TS2379 (most common): inline options types in run/compute
  helpers got `| undefined` added to each optional property.
- TS7022 self-referential implicit any: `const next: number` or
  `const next: number` annotation to break the inference cycle.
- TS6133 unused: 2 sites in chart-line-fft-window
  (`projectFreqX`, `spectrumBarWidthRatio`) + 2 sites in
  chart-line-residual (`positiveColor`, `negativeColor`).

Total: **48**.

## After this patch

`tsc --noEmit -p web/tsconfig.json`: **234** errors total, **0** in
the 24 files. Delta = 282 - 234 = **-48**. Zero new errors anywhere.
`.test.*` files still at zero project-wide. Non-chart-component
files still at zero project-wide.

## What changed (per file, minimal pure-type)

24 files, exactly 2 fixes each. See per-file detail in the commit
message; every fix is one of:
- `{ X?: T }` -> `{ X?: T | undefined }` in inline options types
  of the same-file run/compute helpers.
- `const next = ...` -> `const next: number = ...` to break the
  TS7022 self-reference.
- Remove genuinely unused declared local (only in chart-line-fft-window
  and chart-line-residual; verified zero call sites and zero JSX
  consumers).
