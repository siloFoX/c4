## What changed (per category, minimal)

### TS2379 exactOptional (add `| undefined` to optional properties of TARGET parameter type)
Per the dispatch's exact instruction: add `| undefined` to the
corresponding optional properties of the run/compute options type
in the SAME file. No call-site coalescing, no data-prop changes.

- **chart-line-ewma.tsx** -- `RunLineEwmaOptions { alpha?: number; span?: number; initialEstimate?: number }` -> all three get `| undefined`.
- **chart-line-fft.tsx** -- `computeLineFftSpectrum`'s inline options type `{ detrend?: boolean; excludeDc?: boolean }` -> both get `| undefined`.
- **chart-line-rsi-cross-sig.tsx** -- 3x identical inline `{ rsiLength?: number; signalLength?: number }` across `computeLineRsiCrossSig`, `runLineRsiCrossSig`, `computeLineRsiCrossSigLayout` -> both get `| undefined`. (Single TS2379 error at the call site; the 3 inline type defs are the targets per dispatch instruction.)
- **chart-line-spectrogram.tsx** -- `computeLineSpectrogram`'s inline options `{ windowSize?: number; hopSize?: number; windowMode?: ...; detrend?: boolean; excludeDc?: boolean }` -> all five get `| undefined`.
- **chart-line-supertrend-flip-cross.tsx** -- inline `{ period?: number; multiplier?: number }` (3 sites) -> both get `| undefined`.
- **chart-line-supertrend-mid-cross-sig.tsx** -- inline `{ period?: number; multiplier?: number; signalLength?: number }` -> all three get `| undefined`.
- **chart-line-vroc-cross.tsx** -- inline `{ length?: number; signalLength?: number }` (3 sites) -> both get `| undefined`.
- **chart-line-vsa-cross.tsx** -- inline `{ length?: number; signalLength?: number }` (3 sites) -> both get `| undefined`.

### TS7022 self-referential implicit any (explicit type annotation)
- **chart-line-rsi-cross-sig.tsx** -- 2x `const next = ...` ternary in EMA/Wilder smoothers -> `const next: number = ...`.
- **chart-line-supertrend-flip-cross.tsx** -- `const finalUpper = ...` and `const finalLower = ...` -> `: number` annotation.
- **chart-line-supertrend-mid-cross-sig.tsx** -- same `: number` annotation on `finalUpper` / `finalLower`.
- **chart-line-vroc-cross.tsx**, **chart-line-vsa-cross.tsx**, **chart-line-zlema-cross.tsx** -- each has 1 `const next = ...` -> `const next: number = ...`.

### TS7006 implicit any parameter (annotate the sort callback)
- **chart-line-forecast.tsx** -- 2x `.sort((a, b) => a.x - b.x)` -> `.sort((a: ChartLineForecastPoint, b: ChartLineForecastPoint) => a.x - b.x)`.

### TS18048 + TS2322 possibly-undefined index access (non-null on the array element)
- **chart-line-keltner.tsx** -- `const u = run.upper[i]` and `const l = run.lower[i]` (both `(number | null)[]`) -> `run.upper[i]!` / `run.lower[i]!`. The subsequent `if (u !== null)` then narrows to `number`.

### TS2322 narrow null|undefined -> null (non-null on indexed access)
- **chart-line-supertrend.tsx** -- 6 sites where `basicUpper[i]` / `basicLower[i]` / `finalUpper[i]` / `finalLower[i]` (each `(number | null)[]`) flow into a `number | null` slot -> add `!` non-null on the source.
